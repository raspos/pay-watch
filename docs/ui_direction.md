# PAY WATCH UI·UX 방향 (2026-11-06 확정, 구현은 로드맵 PHASE 13)

핵심 원칙: **Search First** — 첫 화면은 구글처럼 검색창 중심.
사용자 흐름: **회사 검색 → 근속 선택 → 결과 확인 → 비교 및 데이터 탐색**. 설명서를 읽지 않고도 쓸 수 있어야 한다.

## 첫 화면
1. 중앙에 제목 "내 친구는 얼마 벌까?"를 크게 배치.
2. 그 아래 슬로건 "남의 연봉 몰래 보기 프로젝트".
3. 가장 눈에 띄는 요소는 기업 검색창. 기업명 자동완성, 키보드 탐색, 모바일 검색을 제공.
4. 기업 순위, 통계 차트, 대시보드, 복잡한 설명은 첫 화면에 두지 않는다.

## 검색 이후
5. 기업 선택 → 근속 구간 선택 → 결과 화면.
6. 결과 화면은 핵심 추정 범위를 먼저 보여 준다. **공개 기준(로드맵 PHASE 12 통합 검증)을 충족하지 못한 기업에는 검증되지 않은 추정치를 표시하지 않는다.**
7. 기업 평균급여, 산업별 임금곡선, 비교 기능, 데이터 출처·방법론은 결과 화면에서 단계적으로(펼침·탭 등) 확인.
8. PAY WATCH LAB과 다른 분석 기능은 별도 메뉴.
9. 디자인은 미니멀·직관적, **모바일 우선**.

## 표시 원칙(연구 결과 연동)
- 추정 범위는 개인 연봉 분포가 아니라 모형 가정에 따른 집단 평균급여 범위로 표기하고, 정확도가 검증되지 않았음을 숨기지 않는다.
- PHASE 12 완료 전에는 기업별 추정치를 검증된 실제 급여처럼 외부에 공개하지 않는다.

## 범위
- 진행 중인 PHASE 10~12의 개발 범위는 이 방향 때문에 바꾸지 않는다. UI 전면 개편은 PHASE 13에서 수행한다. 이 문서는 계획 기록이며 코드·화면은 수정하지 않았다.

## 디자인 철학과 품질 검증 (2026-11-06 확정)
- 철학: **Search First. Data First. Minimal UI.** AI가 자동 생성한 전형적 대시보드처럼 만들지 않고, 전문 프로덕트 디자이너가 설계한 듯 절제되고 정교하게. 절제된 색, 충분한 여백, 명확한 타이포, 일관된 간격·정렬·그리드, 간결한 상호작용, 정보의 명확한 우선순위. 장식보다 사용성.
- 첫 화면은 "내 친구는 얼마 벌까?", "남의 연봉 몰래 보기 프로젝트", 기업 검색창만 강조(검색창이 시각적 중심). 순위·통계 카드·차트·긴 설명 금지. 검색 예시는 최소한.
- 결과 화면 위계: ① 기업명 ② 근속 구간 ③ 추정 평균연봉 범위 ④ 기업 전체 공시 평균급여 ⑤ 근속 구간별 그래프 ⑥ 상세 분석. 가장 중요한 숫자가 가장 크게. 불필요한 보조 수치·설명문 제거.
- '실험적 추정'과 '집단 평균 추정 범위'라는 성격은 숫자 가까이에 **간결하게** 표시한다. 오해를 막는 필수 정보는 숨기지 않는다.
- 장문 설명은 첫 화면에 두지 않는다. 추정 방법·통계적 가정·데이터 한계·상세 출처·업데이트 이력·검증 결과는 접이식 영역 또는 별도 페이지로. '추정 방법'과 '주의사항'은 펼쳐볼 수 있게 하고, 기본 화면에는 핵심 안내 한 줄. 같은 설명을 여러 곳에 반복하지 않는다.
- 스타일: 라이트 모드 우선, 흰색/밝은 중립 배경, 높은 명도 대비, 강조색 하나, 그라데이션 금지, 그림자·테두리 최소화, **카드 남용 금지**(여백·정렬로 충분하면 카드 없이), 아이콘·이모지 남용 금지, 큰 숫자는 타이포로 강조, 데이터 시각화는 단순·정확.
- 인터랙션: 검색 → 기업 선택 → 근속 선택 → 결과. 추가 클릭 최소화, 근속 변경 즉시 갱신, 불필요한 로딩 애니메이션·튜토리얼·모달 금지, 모바일에서도 같은 정보 위계.
- 화면 구현 후 자체 점검: 이 설명이 첫 화면에 필요한가 / 이 카드는 없애도 되는가 / 가장 궁금한 숫자가 먼저 보이는가 / 3초 안에 목적을 이해하는가 / 모바일에서도 위계가 유지되는가 / 불필요한 클릭이 있는가. 유지할 이유가 불분명한 요소는 삭제하거나 접이식으로.
- 적용 일정: PHASE 11은 기존 범위 안에서 참고, PHASE 12는 데이터·모형 검증에 집중, **PHASE 13에서 UI·UX 전면 개편**, PHASE 14에서 외부 공개용 사이트 완성. 진행 중 작업 범위를 임의로 확대하지 않는다.

## 검색 UX 요구사항 (2026-11-06 추가, 구현은 로드맵 PHASE 13, 설계는 A·B그룹 공통 검색 엔진)
이용자는 법인 정식 명칭이 아니라 일상적인 회사 이름으로 검색한다. 예: '에스케이하이닉스 주식회사'는 'SK하이닉스'로 검색해도 최상단에 나와야 한다.
1. **이름 분리**: legal_name(법적 명칭, 원본 보존), display_name(화면 표시명), search_aliases(검색 별칭)를 분리한다.
2. **법인 표기 정규화**: '주식회사', '(주)', '㈜' 등은 검색 과정에서만 정규화한다. 원본 기업명은 바꾸지 않는다.
3. **한글·영문 표기**: SK/에스케이, LG/엘지, KB/케이비 등은 **확인된 별칭 사전**으로 처리한다. 모든 기업에 기계적 치환을 적용하지 않는다.
4. **표기 변형**: 띄어쓰기, 대소문자, 일부 특수문자 차이를 검색에 반영한다.
5. **표시 우선순위**: 결과에는 공식 법인명보다 이용자에게 익숙한 이름(display_name)을 우선 표시하고, 필요하면 정식 명칭을 보조 정보로 보여 준다.
6. **검색 순위**: 정확한 별칭 일치 → 표시명 일치 → 접두어 일치 → 부분 일치 → 유사어 일치.
7. **그룹핑**: 동일 기업의 여러 국민연금 사업장은 식별 근거가 확인된 경우에만 대표 기업으로 묶는다. 이름만 같다는 이유로 서로 다른 법인을 병합하지 않는다.
8. **식별자 불변**: 기존 국민연금 사업장 ID와 DART 법인코드는 유지한다. 검색 별칭 때문에 기업 식별자가 바뀌어서는 안 된다.
9. **공통 엔진**: A그룹·B그룹 모두 재사용할 수 있는 검색 엔진으로 설계한다.
10. **검증**: 주요 기업 30곳을 표본으로 실제 이용자가 입력할 법한 검색어를 테스트하고 원하는 기업이 상위에 노출되는지 확인한다.
- 새로운 대규모 데이터 수집은 하지 않는다(별칭 사전은 확인된 항목만 수기 관리). 개발 순서는 유지한다.
